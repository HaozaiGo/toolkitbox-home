测试方法

推荐一个浏览器工具之前，我们如何验证它。

“本地处理”不能只靠页面上的一句文案证明。ToolkitBox 使用可公开复现的合成样例、浏览器网络检查、边界输入和独立结果复核，让读者也能在自己的设备上重复验证。

ToolkitBox 维护 · 2026 年 10 月 20 日复核 · 当前参考环境：macOS 上的 Chrome 155

1. 先准备不含真实信息的合成样例

公开测试不会使用客户记录、生产密钥或真实私密日志。JSON 样例使用虚构姓名和保留域名；URL 使用 example.com；正则测试同时包含应匹配、不应匹配、Unicode、空输入和受控长度的长文本。这样既能复现错误，也不会把任何人的数据带进测试。

2. 看网络请求，而不是只看宣传文案

打开开发者工具后，清空 Network 面板、关闭缓存，再执行主要操作并检查新增请求。静态资源、统计脚本和用户输入传输必须分开记录。只有输入与输出留在页面运行环境中，浏览器本地处理的结论才成立。SSL 检查是明确例外，因为查询公网证书必须经过服务器。

3. 使用独立方法复核结果

工具内部显示“成功”并不等于验证完成。JSON 输出会再次解析并与原始结构比较；Base64 输出会解码并逐字节比较；URL 组件会与浏览器原生 URL 解析器对照；正则结果会与预先写好的匹配表比较；SSL 结果则要与公网边缘实际提供的证书核对。

当前复核矩阵

工具主要样例独立复核不能证明的事情
JSON嵌套对象、Unicode、错误逗号重新解析并比较结构语法正确不代表业务字段正确

4. 检查失败路径和移动端

复核包括空输入、错误输入、重复执行、复制或下载、语言切换、键盘焦点和 390 CSS 像素宽的移动端。错误提示应说明失败原因，并且不能无故清空用户输入。导航、工具控件和广告也不能互相覆盖。

5. 明确写出工具边界

本地处理不能让本来敏感的数据自动变安全；合法 JSON 仍可能包含泄露的令牌；有效证书也可能部署在错误的服务上；通过颜色对比度并不代表所有状态都无障碍。ToolkitBox 把这些限制视为结果的一部分，而不是藏在页脚的小字。

更正与复现

浏览器更新改变行为后，我们会重新运行样例，并在更新记录中说明重要修改。报告问题时，请把工具网址、浏览器版本、预期结果、实际结果和不含私密数据的样例发送到 contact@toolkitbox.org。
