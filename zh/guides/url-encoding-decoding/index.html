URL 编码和解码：调试 Web 链接的实用方法

URL 会携带路由、查询参数、跳转目标、追踪字段和页面状态。链接失效时，问题往往藏在编码、参数顺序、保留字符或复制时多出的一个字符里。

先拆成组件再修改

不要把整条 URL 当作一段普通字符串处理。先拆分协议、域名、路径、查询参数和片段，确认问题出在域名、路径、参数值还是 Hash 上。

调试查询参数前先解码

编码后的参数很难阅读。先解码查询字符串，可以看到重复 key、嵌套跳转链接、中文字符、追踪参数和意外混入的空格。如果某个参数本身又是一条 URL，需要单独检查。

只编码需要编码的部分

常见错误是把整条 URL 全部编码，或者在参数值中漏掉保留字符编码。处理链接时应按组件操作：路径、参数名、参数值和片段的规则并不完全一样。

小心 redirect、next 和 callback

带跳转参数的 URL 可能造成安全或统计问题。遇到 redirect、next、return、callback 等字段时，要确认目标域名是否可信，编码层级是否正确。

分享链接前清理敏感信息

链接中可能包含邮箱、文档 ID、会话标识、访问令牌或广告追踪参数。用于工单、截图或公开 issue 前，应删除不必要的私密参数。
